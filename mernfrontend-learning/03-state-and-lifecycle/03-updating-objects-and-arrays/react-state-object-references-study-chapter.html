01 · Start here

The core idea

A JavaScript object has both contents (its properties) and an identity (which particular object it is). These are related, but they are not the same thing.

Remember: Changing a property does not create a new object. Creating a new object does.

React state is a value held by React between renders. When state contains an object, React can compare the previous state value with the next one. For objects, that comparison tells React whether the value is the same object—not whether every property is unchanged.

02 · JavaScript objects

Object identity and references

When you assign an object to another variable, JavaScript copies the reference. Both variables can point to the same object.

const user = { name: "Alice" };
const anotherUser = user; // same object, shared reference

anotherUser.name = "Bob";
console.log(user.name); // "Bob" — the shared object changed
console.log(Object.is(user, anotherUser)); // true

The variables are separate labels, but their value is a reference to the same object. The object's identity stays the same when one of its properties changes.

03 · Two different operations

Mutation vs immutable update

Mutation

Edit a property on the existing object.

user.name = "Bob";
// Object A is still Object A

Contents changed; identity stayed the same.

New object

Make a new object with updated contents.

const nextUser = {
  ...user,
  name: "Bob"
};
// nextUser is Object B

Contents may be similar; identity is new.

Shallow copy: { ...user } creates a new outer object, but nested objects are still shared unless you copy those too.

console.log(Object.is(state.profile, next.profile)); // true: nested object is shared
04 · Identity comparison

What does Object.is() compare?

Object.is(a, b) answers whether two values are the same value. For objects and arrays, this means the same identity/reference. It does not walk through every property and compare them.

ExampleResultWhy
Object.is(user, anotherUser)trueBoth variables point to Object A.
Object.is(user, { ...user })falseThe spread created a different outer object.
user.name = "Bob", then compare user with itselftrueMutation changed a property, not identity.
Conversation checkpoint: When asked whether Object.is(user, newUser) is false after newUser = { ...user }, the answer is false because the outer object reference changed. Same property values do not mean the same object.

For primitive values like strings and numbers, Object.is() compares the values with a few precisely defined edge cases. For this chapter, focus on the object rule: same object means true; separately created objects mean false.

05 · React behavior

How React decides whether to update

When you call a state setter, React schedules state work. If the next state is identical to the current state according to Object.is, React can skip rendering that component's children as an optimization. React may still call the component before concluding it can bail out, so avoid relying on an exact render-call count.

You call the setter
For example, setUser(nextUser).
React compares state values
For object state, same reference means Object.is(previous, next) is true.
React can bail out
If the value is the same, React may skip committing a visible update for that state change.
A changed reference signals new state
A new object lets React process the update and render from the new state.
Why mutation is confusing: If you mutate the object and pass that same reference back, React sees the same state value. The object has changed behind React's back, so the UI may remain stale until some other render happens. A later render might reveal the mutation unexpectedly.

React does not deep-scan your object to find mutations. An unrelated state update can cause a later render that reads the mutated object, which is one reason mutation leads to inconsistent behavior.

06 · Previous values

What happens to the old state object?

With an immutable update, the old object is not instantly erased. It remains a normal JavaScript object. Whether it stays available depends on whether anything can still reach it.

After updateReact state → Object B
name: Bob

If no variable, closure, history entry, or other object still points to Object A, it can eventually be collected.

Old objects may remain reachable on purpose—for example, an event handler closure, an undo-history array, or another variable may still reference them. JavaScript only treats an object as eligible for collection when it is no longer reachable from roots such as active variables and runtime references.

07 · Memory basics

Reachability and garbage collection

JavaScript engines automatically reclaim memory for objects that are no longer reachable. You do not manually free ordinary objects.

Still reachable

A live reference leads to the object, so the engine must preserve it.

const saved = oldObject;
// saved still points to it

No longer reachable

No live reference can get to it, so it is eligible for garbage collection.

oldObject = nextObject;
// if no other reference exists,
// old object may be collected later
“Eligible” does not mean “removed immediately.” The garbage collector chooses when to reclaim memory. Exact timing is an implementation detail.

Updating React state does not itself guarantee the old object disappears. React and JavaScript may hold references temporarily, and your own code may keep references for legitimate reasons.

08 · Put it into practice

React examples

Incorrect: mutate and reuse the same object

function Profile() {
  const [user, setUser] = useState({ name: "Alice" });

  function changeName() {
    user.name = "Bob"; // mutates existing state
    setUser(user);          // same identity
  }

  return <button onClick={changeName}>{user.name}</button>;
}

Correct: create a new object

function Profile() {
  const [user, setUser] = useState({ name: "Alice" });

  function changeName() {
    setUser(previousUser => ({
      ...previousUser,
      name: "Bob"
    })); // new object identity
  }

  return <button onClick={changeName}>{user.name}</button>;
}

The functional setter form receives the latest state value, which is useful when the next state depends on the previous state. For nested state, copy each object along the path you change:

setUser(previous => ({
  ...previous,
  profile: {
    ...previous.profile,
    city: "Mumbai"
  }
}));
09 · Quick review

Summary to remember

  • Objects have properties and identity; those are different things.
  • Assigning one object variable to another copies its reference, so both can point to one object.
  • Mutation changes the existing object; it does not make a new identity.
  • Object spread creates a new shallow outer object.
  • Object.is() compares object identity, not nested properties.
  • React state setters use Object.is to detect identical state and can bail out; mutation can leave the UI stale or inconsistent.
  • Prefer immutable updates that return new objects for changed state.
  • Old objects can remain alive while reachable; unreachable objects become eligible for automatic garbage collection.
One-sentence takeaway: Change state by making a new object, so React can see the new identity and render consistently.
10 · Check yourself

Quiz

1. Two variables point to the same object. If you mutate through one, what does the other see?

Answer: The changed property, because both variables refer to the same object.

2. What does Object.is(user, { ...user }) return?

Answer: false. The spread creates a new outer object, so its identity differs.

3. Does changing user.name create a new object reference?

Answer: No. It changes a property on the existing object.

4. Why can setUser(user) after mutation fail to update the UI as expected?

Answer: The next state is the same object by identity. React can bail out of that state update, while the object has already been mutated. The UI may stay stale until another render.

5. Is { ...state } a deep copy?

Answer: No. It is a shallow copy: the outer object is new, but nested objects are shared unless copied separately.

6. When can the old state object be garbage-collected?

Answer: When it is no longer reachable from any live reference. Collection may happen later; timing is chosen by the JavaScript engine.

7. Predict the output: const a = {x: 1}; const b = a; b.x = 2; Object.is(a,b)

Answer: true. Both names still point to the same object, now with x: 2.
